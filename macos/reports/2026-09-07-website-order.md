## 原因

1. macOS 发布先按 URL 合并记录。字典保留旧 JSON 的顺序，新增作品追加末尾，更新已有作品不会移动其位置。
2. JSON 直接写入上述顺序；Markdown 生成器又按年份倒序排列。因此两个文件既可能与网站不同，也可能彼此不同。
3. 网站展示顺序没有进入发布链。Sitemap 的发现结果还经过 URL 字母排序，不能用来代替网站顺序。

## 修复规则

- 导出时独立读取网站完整项目顺序，不读写增量同步检查点，不调用 AI。
- 验证项目 ID、数量、顺序和链接完整性，拒绝部分列表或错误页面。网站读取失败时不推送，保留已接受记录供重试。
- 合并最新远端数据后，统一排序一次；JSON 与 Markdown 使用同一份列表。Markdown 移除年份分组标题，每件作品的年份字段保持原样。
- 网站未列出的历史作品或并发新增记录完整保留，并在已列作品后维持原有相对顺序。
- 仅更新程序快照即可让旧审核队列使用新输出规则，审核基线、人工编辑、接受状态和同步检查点不会重置。

本次纠正的 170 项 JSON 按 URL 比较，所有字段与 `ac7122a` 完全相同；Markdown 每件作品的内容段也逐项相同，只改变排列及年份分组结构。JSON 与 Markdown 的作品 URL 序列完全一致，前三项均为 `poly cam work → Danmaku → 1bit`。
